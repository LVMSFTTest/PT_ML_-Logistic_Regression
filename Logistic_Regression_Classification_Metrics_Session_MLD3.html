Introduction to Logistic Regression

Why we need an entirely different tool than linear regression the moment the target becomes a category instead of a number.

Definition

In Plain English

Logistic Regression models the relationship between a categorical outcome and one or more input features, using the logistic (sigmoid) function to turn a linear combination of inputs into a probability between 0 and 1 — which is then converted into a class prediction using a threshold (usually 0.5).

Why Not Just Use Linear Regression?

🎓 The Problem With a Straight Line for Yes/No Outcomes

If you fit a plain linear regression line to predict "has disease (1) or not (0)," the line can predict values like -0.3 or 1.8 — numbers that make no sense as a probability. Logistic regression fixes this by squeezing every prediction into the valid [0, 1] range.

Key Characteristics

AspectDetail
OutputProbabilities between 0 and 1
NatureA classification algorithm (despite the name "regression")
Decision BoundaryA threshold (usually 0.5) converts probability into a class
💼 Business Use Case

A hospital wants to predict whether a tumor is malignant from measurements like size and texture. A bank wants to predict whether a loan applicant will default. An email provider wants to predict whether a message is spam. All three are the exact same underlying math problem: predict the probability of a binary outcome.

Sigmoid, Logit & Odds Ratio

The mathematical machinery that turns "any number at all" into "a well-behaved probability" — and back again.

The Sigmoid Function — Definition

In Plain English

The sigmoid function is an S-shaped curve that squeezes any real number into the range (0, 1) — turning the model's raw linear score into something that behaves like a probability.

σ(z) = 1 / (1 + e−z)

Visual — The Sigmoid Curve

The Logit Function — Definition

In Plain English

The logit is the sigmoid's inverse — it takes a probability (0 to 1) and converts it back into an unrestricted real number. It's defined as the natural log of the odds.

logit(p) = ln( p / (1 − p) )

Odds and Odds Ratio — Definition

In Plain English

Odds compare the probability of an event happening to it not happening. An odds ratio compares those odds between two groups — a common way doctors and researchers communicate risk.

Odds = p / (1 − p)   |   Odds Ratio = OddsGroup A / OddsGroup B
💼 Business Use Case — Odds Ratio in Medicine

"Smokers have 3× the odds of developing the disease compared to non-smokers" is an odds ratio of 3 — a phrasing you've almost certainly seen in a health headline. In our breast cancer model, a coefficient's exponentiated value (ecoefficient) gives exactly this kind of odds ratio for a one-unit increase in that feature.

Example

🎓 Worked Example

If a tumor has predicted probability of malignancy p = 0.8:

Odds = 0.8 / 0.2 = 4 (malignant is 4× as likely as benign for this tumor)

Logit = ln(4) ≈ 1.386 (the raw linear score the model produced before the sigmoid squashed it)

Python Code

Pythonimport numpy as np def sigmoid(z): return 1 / (1 + np.exp(-z)) p = sigmoid(1.386) print(f"Probability: {p:.3f}") # ≈ 0.800 odds = p / (1 - p) print(f"Odds: {odds:.2f}") # 4.00

Binary Classification & Business Use Cases

The two-class problem, and why choosing which class is "positive" is itself a meaningful decision.

Definition

In Plain English

Binary classification sorts data into exactly two categories: a positive class (1, the event of interest) and a negative class (0, its absence). Which class you call "positive" should match what you actually care about detecting.

In our breast cancer dataset, sklearn's raw label convention is 0=malignant, 1=benign — but clinically, we should treat malignant as "positive", since that's the condition we're trying to catch. Get this backwards, and your precision/recall numbers will describe the wrong thing entirely, even though the code runs without any error.

Binary Logistic Regression & the Decision Boundary

From a probability to an actual yes/no answer.

Definition

In Plain English

Binary logistic regression estimates the probability of the positive class using the sigmoid function, then applies a threshold (typically 0.5) to convert that probability into a firm classification decision.

Formula

P(Y=1 | X) = σ(b₀ + b₁x₁ + b₂x₂ + ... + bₙxₙ)
If P(Y=1) > threshold → predict class 1, else predict class 0

Example

🎓 Example — Breast Cancer Prediction

For a specific tumor, the model computes P(malignant) = 0.87. Since 0.87 > 0.5, the model predicts malignant. Training itself works by adjusting the coefficients (b) to maximize the likelihood of correctly predicting the training labels — this process is called Maximum Likelihood Estimation.

Visual — Moving the Threshold Changes the Business Trade-off

Lowering the threshold below 0.5 means the model calls more cases "positive" — in a cancer-screening context, this deliberately trades some extra false alarms for a lower chance of missing a real cancer. We demonstrate this exact trade-off with real numbers in the companion notebook.

💼 Business Use Case — Threshold Is a Business Decision, Not Just a Default

A bank approving loans might RAISE the threshold for "predict default" to avoid rejecting too many good customers (protecting revenue). A hospital screening for cancer might LOWER the threshold for "predict malignant" to avoid missing any real cases (protecting lives). The "right" threshold depends entirely on which mistake costs more in that specific business.

Multiclass Classification & Softmax

What happens when there are three or more categories instead of just two.

Definition

In Plain English

Multiclass classification assigns each observation to one of three or more categories. Multiclass logistic regression extends the binary case using the softmax function, which converts raw scores for every class into probabilities that all sum to exactly 1.

Formula

P(class = k) = ez_k / Σj ez_j

Example

🎓 Example — Iris Species (3 Classes)

For a given flower, the model computes raw scores for each species, then softmax converts them into: P(setosa)=0.02, P(versicolor)=0.85, P(virginica)=0.13. Since versicolor has the highest probability, the model predicts versicolor. Notice all three probabilities sum to 1.00.

💼 Business Use Cases for Multiclass

Classifying support tickets into departments (billing / technical / sales), categorizing news articles by topic, recognizing handwritten digits (0-9), or — in a medical context — classifying a tumor into one of several cancer subtypes rather than just "cancer / no cancer."

Visual — Softmax Distributes Probability Across All Classes

All three bars' heights (probabilities) sum to 1.0 — the model picks whichever class has the tallest bar.

Confusion Matrix — Deep Dive

The single most important table in classification — everything else on this page's neighbors (precision, recall, F1, ROC) is just arithmetic on these four numbers.

Definition

In Plain English

A confusion matrix is a grid that shows exactly how many predictions fell into each combination of "what actually happened" and "what the model predicted." It's the raw material every other classification metric is built from.

Why Accuracy Alone Can Lie

Imagine a dataset where only 2% of patients actually have a rare disease. A model that predicts "no disease" for EVERYONE would score 98% accuracy — while catching zero real cases. This is exactly why we look at the full confusion matrix, not just accuracy, whenever classes are imbalanced or mistakes have different costs.

Type I & Type II Errors, Alpha & Beta — Deep Dive

The two ways any classification decision can go wrong — and why business context, not math alone, decides which one to fear more.

Definition

Type I Error (False Positive) — Probability = α

Predicting the positive class when the truth is actually negative — a false alarm. In hypothesis-testing language: rejecting a true null hypothesis. Its rate, α, is exactly the False Positive Rate: α = FP / (FP + TN) = 1 − Specificity.

Type II Error (False Negative) — Probability = β

Predicting the negative class when the truth is actually positive — a missed detection. Its rate, β, equals: β = FN / (FN + TP) = 1 − Recall. And Statistical Power = 1 − β = Recall (Sensitivity) — the exact same "Power" concept from Day 2's hypothesis testing material!

Formula — The Precise Bridge Between Stats and Classification

α (Type I rate) = FP / (FP + TN) = 1 − Specificity = False Positive Rate
β (Type II rate) = FN / (FN + TP) = 1 − Recall   |   Power = 1 − β = Recall
Why "Recall = 1 − β = Power" Exactly — Step by Step

This isn't a coincidence or an approximation — it's the same fraction, just labeled two different ways depending on which field you learned it in. Let's derive it slowly, using our real breast cancer numbers (TP=41, FN=2):

  1. Start with the definition of β. β is "the probability of failing to detect a real positive case" = the fraction of actual positives that got MISSED = FN / (FN + TP) = 1/(1+41) = 1/42 ≈ 0.024 (2.4%).
  2. Now define Recall the same way, from the other direction. Recall is "the fraction of actual positives that got CAUGHT" = TP / (TP + FN) = 41/42 ≈ 0.976 (97.6%).
  3. Notice the denominators are identical — both are dividing by the SAME total (TP + FN = all actual positives = 43 real cancer cases). The only difference is the numerator: β counts the ones we missed (FN), Recall counts the ones we caught (TP).
  4. Since "caught" and "missed" are the only two possibilities for an actual positive case, they must add up to 100% of that group: (fraction caught) + (fraction missed) = 1. In symbols: Recall + β = 1.
  5. Rearranging gives: Recall = 1 − β. Check with real numbers: 1 − 0.024 = 0.976 ✓ — matches exactly.
  6. "Power" is just statistics' name for this same idea. In hypothesis testing, "power" means "the probability of correctly detecting a real effect when one truly exists" — which is precisely what Recall measures for a classifier. Two names, one formula: Power = Recall = 1 − β.

Plain-English summary: out of every 100 real positive cases, some percentage gets caught (that's Recall, that's Power) and the rest gets missed (that's β). Since those two groups cover everyone, they must always sum to 100% — that's the whole "proof" in one sentence.

🎓 Visual — Splitting "All Actual Positives" Into Caught vs Missed

The bar's two segments always add up to the full 100% — there's no third option for an actual positive case. That's the entire reason Recall and β are just two ways of describing the same split.

The Decision Framework — "Which Error Costs More?"

Ask This Question Every Time

"What does a false positive cost me? What does a false negative cost me? Whichever is more expensive, minimize THAT error — even if it means accepting more of the other." This single question is the practical heart of "when is it very important."

Business Deep Dive — Four Domains, Four Different Answers

💼 1. Medical Diagnosis (Cancer Screening) — Minimize Type II (β)

H₀: "the patient does not have cancer."

Type I (FP): a healthy patient is flagged as possibly having cancer → cost: anxiety, an unnecessary biopsy, follow-up appointments. Unpleasant, but recoverable.

Type II (FN): an actual cancer patient is told they're healthy → cost: the disease progresses untreated, potentially becoming fatal.

Priority: minimize β (maximize recall/sensitivity), even at the cost of a higher α. Our real model reflects this well: only 2 missed cancers (FN) out of 43, vs just 1 false alarm (FP).

💼 2. Spam Email Filtering — Minimize Type I (α)

H₀: "this email is legitimate."

Type I (FP): a real, important email (a job offer, a client message) gets marked as spam and hidden → cost: potentially high, if the user never sees it.

Type II (FN): a spam email slips into the inbox → cost: minor annoyance, quickly deleted.

Priority: minimize α (maximize precision for "legitimate") — most spam filters are deliberately tuned to let some spam through rather than risk burying real mail.

💼 3. Credit Card Fraud Detection — Depends on the Cost Ratio

H₀: "this transaction is legitimate."

Type I (FP): a legitimate purchase gets blocked → cost: customer frustration, possible loss of that customer.

Type II (FN): a fraudulent transaction goes through → cost: direct financial loss, chargebacks.

Priority: genuinely depends on the numbers — banks often calculate the average dollar cost of each error type and tune the threshold to that specific ratio, rather than picking one error type to minimize outright. A great open discussion question for the Workshop.

💼 4. Airport Security Screening — Minimize Type II (β)

Type I (FP): an innocent passenger gets extra screening → cost: inconvenience, delay.

Type II (FN): an actual threat passes through undetected → cost: potentially catastrophic.

Priority: strongly minimize β, similar to medical screening — accept many false alarms to avoid ever missing a real threat.

When Is This "Very Important"?

This trade-off matters most whenever: (1) the two error types have meaningfully different real-world costs, (2) the classes are imbalanced (so accuracy alone is misleading), or (3) the decision affects health, safety, money, or legal outcomes. In low-stakes, balanced-cost situations (e.g., recommending a movie), the distinction matters far less.

Choosing a Metric — Business Framing

Optimize for Recall when...

  • Missing a positive case is costly (cancer, fraud, security threats)
  • You can tolerate more false alarms

Optimize for Precision when...

  • A false alarm is costly (spam filtering, blocking legitimate transactions)
  • You can tolerate missing a few positive cases
F1-Score — When to Use It

Use F1 when you want ONE number balancing both concerns roughly equally, or when comparing multiple models and neither precision nor recall clearly matters more. It's the harmonic mean, which punishes a big imbalance between precision and recall more than a simple average would.

ROC Curve & AUC

A single picture showing a model's performance across EVERY possible threshold at once — not just the default 0.5.

Definition

In Plain English

The ROC (Receiver Operating Characteristic) curve plots True Positive Rate against False Positive Rate as the classification threshold sweeps from 0 to 1. AUC (Area Under the Curve) condenses that entire curve into one number summarizing overall discriminative ability.

Formula / Axes

Y-axis: TPR (Recall) = TP/(TP+FN)    X-axis: FPR = FP/(FP+TN) = α
Never Forget the ROC Axes Again — Memory Tips

The core trick that makes both formulas easy to derive on the spot: both axes are built the exact same way — (something we predicted positive) ÷ (a group of ACTUAL cases) — the only difference is which actual group sits in the denominator.

  • Y-axis (vertical) = True Positive Rate. Denominator = all ACTUAL positives (TP+FN). Question it answers: "Of everyone who truly has the condition, what fraction did we correctly catch?" This is a GOOD rate — you want it HIGH.
  • X-axis (horizontal) = False Positive Rate. Denominator = all ACTUAL negatives (FP+TN). Question it answers: "Of everyone who's truly healthy, what fraction did we wrongly scare?" This is a BAD rate — you want it LOW.

Three different memory tricks — use whichever sticks for you:

  1. The "good news goes up" trick. Good outcomes (catching real positives) get plotted going UP the Y-axis, like a success climbing higher. Bad outcomes (false alarms) get plotted going ACROSS the X-axis, like a mistake spreading sideways rather than being an achievement.
  2. The "best model lives top-left" trick. A perfect classifier sits at the TOP-LEFT corner: (FPR=0, TPR=1) — zero false alarms, every real case caught. If you remember "the trophy corner is top-left," you can always reconstruct that UP must be the rate you want high (TPR) and RIGHT must be the rate you want low (FPR) — there's no other way to make top-left the best spot.
  3. The weather-forecaster trick. Picture a forecaster predicting rain. Y-axis = "of the days it actually rained, how often did they correctly call it?" — their hit rate, something to be proud of, so it climbs UP. X-axis = "of the sunny days, how often did they wrongly cry 'rain'?" — their false-alarm habit, an embarrassing tally that spreads ACROSS, not up.

One more anchor point: the diagonal dashed line always runs from bottom-left (0,0) to top-right (1,1) — a coin-flip model that's just as likely to produce a hit as a false alarm. Any model worth using should bulge UP and to the LEFT of that line, toward the trophy corner.

Applied to our real numbers: our breast cancer model has TPR≈97.6% (climbs almost to the top) and FPR≈1.4% (barely moves right) — which is exactly why its curve hugs the top-left corner so tightly in the chart below.

AUC-ROC vs AUC-PRC

AUC-ROC can look overly optimistic on heavily imbalanced datasets. AUC-PRC (Precision-Recall Curve) is often preferred in that situation, since it focuses specifically on how well the model handles the minority (often more important) class.

Pro Tips

Habits that separate a classifier that "runs" from one that's actually safe to deploy.

🎯 Positive Class
Always explicitly state (and set in code via pos_label) which class is "positive" — never assume it matches sklearn's default. Getting this backwards silently flips your precision/recall numbers.
🎯 Beyond Accuracy
Never report accuracy alone on an imbalanced dataset. Always pair it with precision, recall, and a look at the full confusion matrix.
⚖️ Threshold
The 0.5 threshold is a default, not a law. Explicitly choose a threshold based on the real cost of Type I vs Type II errors for your specific business problem.
⚖️ Threshold
Plot precision and recall against threshold together (a "precision-recall vs threshold" chart) to pick a threshold deliberately rather than guessing.
📏 Scaling
Unlike plain linear regression, logistic regression in sklearn uses regularization by default — ALWAYS scale your features first, or large-scale features will be unfairly penalized.
📊 Class Imbalance
If one class is rare (fraud, rare disease), check class balance FIRST. Consider stratified splitting, class weighting, or resampling techniques before trusting any metric.
📈 ROC vs PRC
On heavily imbalanced data, prefer the Precision-Recall curve (AUC-PRC) over ROC-AUC — ROC can look deceptively good even when the minority class is handled poorly.
🔍 Multiclass
For multiclass problems, look at the FULL confusion matrix, not just overall accuracy — it tells you exactly which classes get confused with which.
💼 Business Framing
Before building anything, explicitly write down: "what does a false positive cost us? What does a false negative cost us?" This single exercise should drive your metric choice and threshold from the very start of the project.
🧪 Validation
Use a stratified train/test split for classification (not a plain random split) to make sure rare classes are still represented proportionally in both sets.

Interview Questions

Common questions asked in Data Science / ML interviews on this topic. Click a question to reveal the answer.

Q1. Why can't we just use linear regression for a classification problem? ▾
Linear regression can output values far outside the [0,1] range, which makes no sense as a probability, and it doesn't naturally model the S-shaped relationship between features and the probability of an event. Logistic regression solves both problems using the sigmoid function to constrain output between 0 and 1.
Q2. Explain the confusion matrix and its four components. ▾
A confusion matrix cross-tabulates actual vs predicted classes. True Positives (TP) and True Negatives (TN) are correct predictions. False Positives (FP, Type I error) are cases wrongly predicted positive; False Negatives (FN, Type II error) are cases wrongly predicted negative. Every other classification metric — accuracy, precision, recall, specificity, F1 — is calculated from these four numbers.
Q3. What's the difference between Type I and Type II errors, and when does each matter most? ▾
A Type I error (false positive) incorrectly flags something as positive when it isn't; a Type II error (false negative) misses a true positive. Which matters more depends entirely on the relative cost of each mistake in context: in medical screening or security, Type II errors (missed detections) are usually far more dangerous; in spam filtering, Type I errors (blocking legitimate content) are often costlier.
Q4. How are alpha, beta, and statistical power related to precision and recall? ▾
Alpha (the Type I error rate) equals the False Positive Rate: FP/(FP+TN), which is also 1 minus Specificity. Beta (the Type II error rate) equals FN/(FN+TP), which is 1 minus Recall. Statistical power, defined as 1-beta, is therefore mathematically identical to Recall (Sensitivity) — the same concept viewed through a hypothesis-testing lens versus a classification lens.
Q5. When would you prioritize precision over recall, or vice versa? ▾
Prioritize recall when missing a positive case is costly and false alarms are cheap to handle (cancer screening, fraud, security threats). Prioritize precision when a false alarm is costly and missing some positive cases is more tolerable (spam filtering, blocking legitimate transactions). When neither clearly dominates, F1-score offers a balanced single metric.
Q6. Why is accuracy often a poor metric for imbalanced classification problems? ▾
With a heavily skewed class distribution (e.g., 98% negative, 2% positive), a model that always predicts the majority class achieves high accuracy while being completely useless at detecting the minority class. Precision, recall, F1, and a full confusion matrix reveal this failure, while accuracy alone hides it.
Q7. What is the ROC curve, and what does AUC tell you? ▾
The ROC curve plots True Positive Rate against False Positive Rate as the classification threshold varies from 0 to 1, showing the full trade-off a model offers. AUC (Area Under the Curve) condenses this into a single number: 0.5 means no better than random guessing, and 1.0 means perfect separation between classes, regardless of threshold choice.
Q8. How does multiclass logistic regression differ from binary logistic regression? ▾
Binary logistic regression uses the sigmoid function to estimate the probability of a single positive class. Multiclass logistic regression uses the softmax function instead, computing a probability for every possible class simultaneously such that they all sum to 1, then predicting whichever class has the highest probability.
Q9. Why does feature scaling matter more for logistic regression than for plain linear regression? ▾
Scikit-learn's LogisticRegression applies L2 regularization by default, which penalizes large coefficients. Features on a larger numeric scale would otherwise need smaller coefficients to have the same effect, making them appear artificially "less important" under regularization unless all features are scaled to a comparable range first.
Q10. How would you decide on a classification threshold other than the default 0.5? ▾
Estimate (or look up) the real-world cost of a false positive and a false negative for your specific problem, then sweep across thresholds computing the total expected cost at each one (cost = FP_count × FP_cost + FN_count × FN_cost), choosing the threshold that minimizes total cost. This turns threshold selection into a business decision backed by data, not just a coding default.
Q11. What's the difference between odds and probability, and why does logistic regression use odds? ▾
Probability ranges from 0 to 1; odds (p/(1-p)) range from 0 to infinity, and the log-odds (logit) range across all real numbers — exactly matching the range of a linear combination of features. This is precisely why logistic regression models the log-odds as a linear function of the inputs, then converts back to probability via the sigmoid.
Q12. In a multiclass confusion matrix, how do you interpret off-diagonal cells? ▾
Each off-diagonal cell (row = actual class, column = predicted class) shows exactly how many instances of one class were mistakenly predicted as another specific class. This is far more informative than an overall accuracy number, since it identifies precisely which pairs of classes the model tends to confuse — useful for guiding feature engineering or gathering more targeted training data.
